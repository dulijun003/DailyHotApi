# 大纲设计

## 1. 先定"一句话核心判断"

写大纲之前，先回答：**这篇文章最终要告诉读者的那一句话是什么？**
写不出来，说明研究还没想透，先回到笔记里找答案。

- ❌ "本文全面介绍了 AI Agent 的发展"（这只是主题，不是判断）
- ✅ "AI Agent 真正的门槛不是模型能力，而是企业愿不愿意把决策权交出去"

## 2. 常用结构模板（按文章类型选择）

| 类型 | 结构 | 适合 |
|---|---|---|
| **问题—分析—解答** | 现象/问题 → 原因拆解 → 关键机制 → 解法/判断 | 大多数分析文 |
| **金字塔（结论先行）** | 核心结论 → 3 个支撑论点（每个论点配证据）→ 含义与建议 | 商业分析、决策参考 |
| **时间线演进** | 起源 → 关键转折 1/2/3 → 现状 → 下一步 | 行业史、技术演进 |
| **对比评测** | 评测框架 → 逐项对比 → 场景化推荐 → 结论 | 选型、比较 |
| **破除迷思** | 流行看法 → 证据反驳 1/2/3 → 更准确的认知 → 启示 | 反常识、科普 |
| **教程递进** | 为什么要学 → 原理 → 步骤 1…N → 常见坑 → 进阶 | 深度教程 |
| **特稿叙事** | 场景开头 → 人物/事件推进 → 拉远看大背景 → 回到人物 | 故事型深度稿 |

## 3. 标题

给出 3 个候选标题：

- **信息型**：说清楚文章讲什么。例如"AI Agent 落地两年：12 个企业案例里的真问题"
- **观点型**：直接亮出判断。例如"AI Agent 的瓶颈不在模型，而在组织"
- **悬念型**：用问题或反差吸引人。例如"为什么花了几百万的 AI Agent，最后只用来写周报？"

标题要求：

- 不超过 30 字
- 不用"震惊""万字长文"这类低质感的词
- 不承诺正文给不了的东西

## 4. 开头钩子（前 100 字决定读者是否继续读）

可以选以下方式之一：

- **反常识事实**："2025 年，X 的数量翻了三倍，但 Y 反而下降了。"
- **具体场景**：从一个真实的人或事开始
- **尖锐问题**：问出读者心里想问但没人回答的问题
- **关键数据**：一个让人意外的数字
- **冲突或悖论**：两个看起来矛盾的事实

开头**避免**：

- "随着……的发展"
- "在当今……时代"
- 下定义
- 自我介绍

## 5. 大纲格式（04-outline.md）

```markdown
# 大纲：《推荐标题》

候选标题：A ｜ B ｜ C（推荐 B，理由：……）
核心判断：……（一句话）
论证主线：§1 提出问题 → §2 拆解原因 → §3 关键机制 → §4 反方与边界 → §5 判断与建议
目标篇幅：6000 字

## 开头（约 400 字）
- 钩子：[F03] 反常识数据……
- 引出问题：……

## §1 小标题（约 1200 字）
- 核心论点：……
- 证据：[F01][F05][F07]
- 案例：……
- 本节结尾过渡到 §2：……

……

## 结尾（约 400 字）
- 落点：回到开头的问题，给出判断 + 2–3 条可操作建议 / 一个开放问题
```

## 6. 大纲自检

- [ ] 每节的核心论点都能用一句话说清
- [ ] 每节都有至少 2 条证据支撑
- [ ] 节与节之间有逻辑递进，不是平行罗列
- [ ] 有一节或一段专门回应反方观点或讨论边界
- [ ] 字数分配加总等于目标篇幅；最重要的那一节篇幅最长
- [ ] 读完大纲，能预测读者会在哪里觉得"原来如此"
