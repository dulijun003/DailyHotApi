# 第 6 步：深度研究

这一步分为五个阶段：并行研究、汇总、独立核查、写学习报告、引用校验。规模按 `state.md` 里的研究深度执行：

| 研究深度 | 视角数 | 每个子问题的最少来源数 | 核查范围 |
|---|---|---|---|
| 轻量 | 3 | 2 | 10–15 条关键论断 |
| 标准 | 5 | 3 | 20–40 条关键论断 |
| 深入 | 5 | 5 | 全部关键论断；汇总后针对缺口再补搜一轮 |

## 6.1 并行研究（每个视角一个子 Agent）

为 `brief.md` 里的每个视角开一个子 Agent，同时运行。子 Agent 看不到当前的对话，所以**任务说明必须完整、独立**。用下面的模板填写：

```
你是一名研究员，负责一项深度研究中的一个视角。今天是 {日期}。

【总研究主题】{研究主题}
【核心问题】{核心问题}
【你负责的视角】{视角名}：{视角目的}
【子问题】
1. ……
2. ……
【检索方向】{关键词与中英文检索侧重}
【不研究】{边界}

要求：
1. 联网检索，每个子问题至少查阅 {最少来源数} 个独立来源。优先 A 级来源（官方文档、论文、官方博客、
   一手数据），其次 B 级（一线工程博客、权威媒体原创报道）。C 级（自媒体、转载）只作线索，
   结论必须回溯到 A 级或 B 级来源。
2. 会随时间变化的信息（产品、版本、价格、市场格局），以近 12 个月的来源为准，并注明来源日期。
3. 不编造。查不到就写"未找到可靠来源"。引文必须是原文摘录，不能是你的转述。
4. 来源之间说法冲突时，把各方说法和出处都列出来，不要自行选一个。
5. 区分事实和观点：观点要注明是谁的观点。

按下面的格式写入文件 {目录}/notes/{视角编号}-{视角英文短名}.md：

# 视角 {N}：{视角名}
## 子问题 1：……
### 发现
- 【事实】……［{视角编号}-S1］
- 【观点】某某认为……［{视角编号}-S2］
### 冲突与不确定
- ……
## 子问题 2：……
...
## 本视角小结（3–5 条）
## 信源
- [{视角编号}-S1] 标题｜发布方｜发布日期｜等级 A/B/C｜URL
  摘录："原文关键句"

信源编号必须带视角前缀，例如视角 4 写成 [4-S1]、[4-S2]，方便汇总时合并。

完成后只回复：文件路径 + 3 条最重要的发现（每条一句话）。
```

不能开子 Agent 时，自己按这个模板逐个视角完成，产出格式不变。

## 6.2 汇总

所有子 Agent 完成后：

1. 读取全部 `notes/`。
2. 把各视角的信源合并成 `sources.md`：
   - **按 URL 去重**（先规范化：去掉末尾斜杠和 `www.`、语言路径如 `/en-us/`）；
   - 合并后统一编号为 G1、G2……，每条标注被哪些视角引用；
   - 文末附一张**编号对照表**（如 `4-S14 → G15`）。之后写报告时，**每次引用都按对照表查编号**，不要凭记忆写。
   - 条目多时，写一个小脚本完成合并和对照表，不要手工整理。
3. 列出**关键论断清单**：最终会写进报告或文章的核心结论、数据、引文，通常 15–40 条，每条附信源编号。
4. 检查覆盖：`brief.md` 里每个子问题都要有答案，或者明确写"未找到可靠来源"。缺口较大时，针对缺口补搜一次。

## 6.3 独立核查（再开一个子 Agent，核查范围按研究深度）

核查员和研究员必须分开：自己核查自己的结论，很难发现问题。任务说明模板：

```
你是一名事实核查员，任务是挑错，不是确认。今天是 {日期}。

下面是一份关键论断清单，每条都附有信源（标题、URL、摘录）。逐条核查：
1. 打开信源，确认信源真的支持这条论断（不是断章取义，也不是过度引申）。
2. 确认信息没有过时：有没有更新的版本、数据或者相反的结论？
3. 数据和引文要逐字核对。
4. 对有疑问的论断，独立检索一次，看有没有反面证据。

每条给出结论：
✅ 成立　⚠️ 需修正（写明怎么改）　❌ 不成立或无法证实（写明原因）　🕐 已过时（给出新信息和来源）

写入 {目录}/factcheck.md，用表格：编号｜论断｜结论｜说明｜依据。
最后统计各类结论的数量。

【关键论断清单】
……
```

根据核查结果修正：⚠️ 按建议改；❌ 删掉，或者降级为"有说法认为……，但未能证实"；🕐 换成新信息。所有修正都记录在 `factcheck.md` 末尾。

## 6.4 学习报告（`report.md`）

学习报告写给用户自己：要完整、可追溯，保留不确定性。除非用户选的是"只学习不发布"（此时按用户选的篇幅写），否则篇幅不设限，以讲清楚为准。

```markdown
# {研究主题}：学习报告
> 研究日期｜信源数｜核查结果：✅ X 条　⚠️ X 条　❌ X 条

## 一句话结论

## 核心结论（5–8 条，每条附信源）

## 知识框架
按"是什么 → 有什么 → 如何做 → 怎么用"四层组织，用费曼的方式讲：
每个概念先用一句大白话解释，再展开细节。

## 分视角发现
### 视角 1：……
...

## 争议与不确定
各方说法和各自的依据，以及目前没有定论的问题。

## 对照选题地图
本次研究回答了地图上的哪些题，还有哪些题没覆盖，建议下一步研究什么。

## 给你的行动建议
结合用户的层次和学习目的：接下来学什么、做什么练习或项目。

## 信源
（引用 sources.md）
```

## 6.5 引用校验（写完报告后必须做）

写作时最容易出的错，是把信源编号张冠李戴。用脚本或逐条检查：

1. 抽出报告中出现的所有编号，确认每个都在 `sources.md` 里存在；
2. 对每个编号，核对它在 `sources.md` 里的标题和摘录，确认它**确实支持**报告里引用它的那句话；
3. 被核查判为 ❌ 的论断，确认没有出现在报告里；判为 ⚠️ 的，确认用的是修正后的说法；
4. 字数按第 3 步的统一口径统计，确认在目标的 ±10% 以内。

校验发现的问题当场改掉，并在 `factcheck.md` 末尾记一笔。

完成后更新 `state.md`。平台是"只学习不发布"时，跳到第 9 步；否则进入第 7 步。
