# 第 8 步：配图

## 8.1 逐个分析占位符

先通读全文，确定整体基调、读者和核心主题；再针对 `article.md` 里的每个 `[配图N｜…]`，结合所在段落的上下文，判断这张图要承担什么功能：

| 内容类型 | 例子 | 配图来源 |
|---|---|---|
| **封面** | 文章第一张图 | AI 生成背景，需要文字时用代码叠加（见 8.4） |
| **抽象 / 概念型** | 解释一个理念、一种趋势、一种感受 | AI 生成：把抽象概念转译成通用、易懂的视觉隐喻 |
| **流程 / 结构型** | 步骤、架构、对比、时间线、关系 | **代码绘制**：Mermaid，或 HTML/SVG 渲染成 PNG |
| **数据型** | 统计数字、趋势、份额 | **代码绘制**图表，数据来自 `sources.md`，图下方注明数据来源 |
| **实体 / 产品型** | 具体的产品界面、真实人物、真实地点、真实事件 | **官方来源**：官网、官方新闻稿、官方媒体资料库，注明出处 |
| **知识卡片**（小红书） | 一图讲一个要点 | **代码排版**生成 3:4 卡片 |

每张图都必须提供**信息增益**：帮读者理解、记忆或感受，而不是把文字再画一遍。

## 8.2 AI 生成的图

1. **统一风格**：所有生成图都使用用户在第 3 步选的风格，用同一套风格描述，配色也保持一致。
2. **提示词结构**：主体 + 场景 + 构图 + 风格 + 配色 + 光线 + 画幅比例。具体描述画面，不要只写抽象的概念词。
3. **不让 AI 在图里写字。** 提示词里注明"no text, no letters"。需要文字的图，用代码叠加。
4. **尺寸**：按 `platforms.md` 里的平台比例生成。
5. **不能生成**真实人物的肖像、真实品牌的 Logo 或产品图，也不能生成可能被误认为真实照片的新闻场景。

## 8.3 代码绘制的图

- 流程图、架构图、时间线：优先用 Mermaid。环境里能渲染时导出 PNG；不能渲染时，在文章里保留 Mermaid 代码，并提醒用户用支持 Mermaid 的工具导出。
- 数据图表、知识卡片、带文字的封面：写 HTML/SVG，用无头浏览器截图导出 PNG。中文字体要确认能正常显示，不能出现方块。
- 配色和生成图的风格保持协调。

## 8.4 带文字的封面

1. 用 AI 生成一张背景图，构图上留出放文字的空间。
2. 用 HTML 把标题文字叠加上去：字号大、对比强，在手机缩略图尺寸下也能看清。
3. 截图导出为平台要求的尺寸。

## 8.5 官方来源的图

- 只用官网、官方新闻稿、官方媒体资料库、官方文档里的图片。
- 记录来源 URL，在图片下方注明"图片来源：……"。
- 找不到合适的官方图片时，改用代码绘制的示意图。**不要从搜索引擎结果里随手取一张来用。**

## 8.6 自查

每张图生成或获取之后，**自己看一遍**再用：

- 和所在段落的内容是否匹配？
- 有没有错字、乱码、畸形的手、多余的文字？
- 尺寸和比例对不对？
- 所有生成图的风格是否统一？

有问题就重新生成，同一张图最多重试 3 次。还是不行，就换一种来源，或者保留占位并在交付时说明。

## 8.7 回填

- 图片存入 `images/`，按顺序命名：`01-cover.png`、`02-xxx.png`……
- 把 `article.md` 里的占位符替换成 `![图片说明](images/02-xxx.png)`。图片说明写清楚这张图在讲什么，同时作为替代文字。
- 官方来源和数据图，在图片下面加一行出处。
- 在 `images/credits.md` 里列出每张图的类型、来源或生图提示词。
