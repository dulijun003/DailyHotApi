# 第 9 步：交付

## 9.1 发布前检查

逐项确认，有问题先修好：

- [ ] 文章（或报告）中每个事实性论断都能在 `sources.md` 里找到出处，编号与内容对得上（6.5 引用校验已完成），并且没有被 `factcheck.md` 判为 ❌
- [ ] 篇幅（按第 3 步的字数统计口径）、标题字数、格式都符合平台规范（`platforms.md`）
- [ ] 所有图片都已回填，没有残留的占位符（只学习模式跳过）
- [ ] 每张图都有出处或生成记录（`images/credits.md`），没有来源不明的图片（只学习模式跳过）
- [ ] 没有残留的 AI 腔套话（7.4 的清单）

## 9.2 终稿审阅

- **分步骤模式**：展示文章全文（只学习模式下，发送 `report.md` 并展示报告目录和核心结论），问"直接用，还是要修改哪里？"按反馈修改，最多来回 3 轮，之后再交付。
- **自动化模式**：直接交付。

## 9.3 交付消息

```
✅ 完成：{研究主题}

📄 成品文章：article.md（{平台}，{实际字数} 字，{N} 张图）
   标题：……
   {如果篇幅和目标不符：材料足够写 X 字，比目标少 Y 字，原因是……}

📚 学习报告：report.md（核查结果：✅ X　⚠️ X　❌ X）
   一句话结论：……

🗂 其他文件：
- topic-map.md　选题地图（{20/40} 题）
- interview.md　访谈记录
- requirements.md　需求确认单
- brief.md　研究简报
- prompts.md　研究提示词（1 个核心 + 5 个聚焦，可以拿到别的工具里跑）
- sources.md / factcheck.md　信源与核查记录
- images/　配图和来源记录

💡 接下来可以：
- 用同一份研究，再写一篇发到别的平台（例如"把这篇改成小红书"），不用重新研究
- 研究选题地图里还没覆盖的题：第 X、Y 题
```

### 只学习不发布模式的交付消息

```
✅ 完成：{研究主题}

📚 学习报告：report.md（{实际字数} 字，目标 {目标字数} 字，{风格}）
   核查结果：{N} 条关键论断 → ✅ X　⚠️ X（已修正）　❌ X
   一句话结论：……
   {如果篇幅和目标不符：材料足够写 X 字，原因是……}

🗂 其他文件：topic-map.md、interview.md、requirements.md、brief.md、prompts.md、
   notes/、sources.md、claims.md、factcheck.md

💡 接下来可以：
- 用这份研究写一篇文章，例如"写成公众号文章""写成 X 长推文"，从第 7 步开始，不用重新研究
- 研究选题地图里报告推荐的下一题：第 X 题
```

## 9.4 后续请求

- **改写到其他平台，或者从学习报告写成文章**：读取 `report.md` 和 `requirements.md`，按第 3 步问新平台的形态（如 X 的发布形态）、篇幅、配图数量、语言，再问风格和受众是否沿用（学习模式下受众原本是用户自己，写文章时必须重新确定受众），然后从第 7 步开始做。新文章存为 `article-<平台>.md`。
- **继续研究地图上的别的题**：新建研究目录，从第 3 步开始。第 1、2 步的结果直接复用，把 `topic-map.md` 复制过去。
