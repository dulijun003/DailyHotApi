# 第 9 步：交付

## 9.1 发布前检查

逐项确认，有问题先修好：

- [ ] 文章中每个事实性论断都能在 `sources.md` 里找到出处，并且没有被 `factcheck.md` 判为 ❌
- [ ] 篇幅、标题字数、格式都符合平台规范（`platforms.md`）
- [ ] 所有图片都已回填，没有残留的占位符
- [ ] 每张图都有出处或生成记录（`images/credits.md`），没有来源不明的图片
- [ ] 没有残留的 AI 腔套话（7.4 的清单）

## 9.2 终稿审阅

- **分步骤模式**：展示文章全文，问"直接用，还是要修改哪里？"按反馈修改，最多来回 3 轮，之后再交付。
- **自动化模式**：直接交付。

## 9.3 交付消息

```
✅ 完成：{研究主题}

📄 成品文章：article.md（{平台}，{实际字数} 字，{N} 张图）
   标题：……
   {如果篇幅和目标不符：材料足够写 X 字，比目标少 Y 字，原因是……}

📚 学习报告：report.md（核查结果：✅ X　⚠️ X　❌ X）
   一句话结论：……

🗂 其他文件：
- topic-map.md　选题地图（{20/40} 题）
- interview.md　访谈记录
- requirements.md　需求确认单
- brief.md　研究简报
- prompts.md　研究提示词（1 个核心 + 5 个聚焦，可以拿到别的工具里跑）
- sources.md / factcheck.md　信源与核查记录
- images/　配图和来源记录

💡 接下来可以：
- 用同一份研究，再写一篇发到别的平台（例如"把这篇改成小红书"），不用重新研究
- 研究选题地图里还没覆盖的题：第 X、Y 题
```

## 9.4 后续请求

- **改写到其他平台**：读取 `report.md` 和 `requirements.md`，问一下新平台的篇幅、配图数量和风格要不要沿用，然后从第 7 步开始做。新文章存为 `article-<平台>.md`。
- **继续研究地图上的别的题**：新建研究目录，从第 3 步开始。第 1、2 步的结果直接复用，把 `topic-map.md` 复制过去。
