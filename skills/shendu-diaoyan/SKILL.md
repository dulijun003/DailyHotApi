# 深度调研与图文写作

把一个模糊的领域兴趣，一步一步变成两份产出：

1. **学习报告**：写给用户自己，内容完整、可追溯、标出不确定项。
2. **成品图文文章**：写给读者，按目标平台的规范写好、排好、配好图，可以直接发布。

两份产出共用同一份研究，研究只做一次。

## 入口判断

先看用户想做什么，再选择入口：

| 用户的意思 | 入口 |
|---|---|
| 深度研究某个领域 / 从研究到发文 / 没说清楚 | 从第 1 步开始，走完整流程 |
| 只研究，不写文章 | 完整流程，第 3 步的平台选"只学习不发布" |
| 用已有的研究写文章（某个研究目录已经有 `report.md`） | 读取该目录的 `state.md`，从第 7 步开始 |
| 给一篇现成的文章配图 | 只执行第 8 步，配图前先问配图数量、风格和平台 |
| 继续上次的研究 | 读取该目录的 `state.md`，从记录的下一步继续 |

## 九个步骤

每一步的详细做法在 `references/` 里，**执行到哪一步，再读哪一步的文件**，不要一次全部读完。

| 步骤 | 文件 | 用户要做的选择 | 产出文件 |
|---|---|---|---|
| 1 启动研究 | `references/01-start.md` | 领域关键词、当前层次、学习目的、研究模式 | `state.md` |
| 2 选题地图 | `references/02-topic-map.md` | 20 题还是 40 题；看完后选研究主题 | `topic-map.md` |
| 3 研究与发布参数 | `references/03-params.md` | 澄清轮数、平台、研究深度、篇幅、配图数量和风格、语言 | `state.md` |
| 4 澄清访谈 | `references/04-interview.md` | 每轮一道多选题；最后确认需求确认单 | `interview.md`、`requirements.md` |
| 5 研究简报 | `references/05-brief.md` | 确认研究计划（分步骤模式） | `brief.md`、`prompts.md` |
| 6 深度研究 | `references/06-research.md` | 无 | `notes/`、`sources.md`、`factcheck.md`、`report.md` |
| 7 写作与排版 | `references/07-writing.md`，平台规范见 `references/platforms.md` | 选标题和角度（分步骤模式） | `article.md` |
| 8 配图 | `references/08-illustration.md` | 无 | `images/`，并回填到 `article.md` |
| 9 交付 | `references/09-delivery.md` | 终稿审阅（分步骤模式） | 交付清单 |

如果第 3 步选了"只学习不发布"，第 6 步完成后直接跳到第 9 步。

## 两种研究模式

- **分步骤**：第 5 步（研究简报）、第 7 步（选标题）、第 9 步（终稿审阅）都停下来，等用户确认。
- **自动化**：这三处不停，直接采用推荐方案往下走，最后一次交付。

**无论哪种模式，第 1–4 步的选择都必须由用户亲自做。** 尤其是澄清轮数和篇幅，任何时候都不预选、不代选。

## 交互规则

1. **一次只推进一步。** 展示这一步的选项，然后停下来等用户回复。不要替用户做选择，也不要一口气连跑几步。
2. **选项格式统一**：用小写字母编号（a、b、c…），注明单选还是多选；需要时最后加一个"其他（请直接写）"。示例：

   ```
   **当前层次**（单选，回复字母）
   a) 小白（完全陌生）
   b) 入门（理论储备）
   ...
   ```

3. **用户随时可以说**：
   - "推荐"或"跳过"：这一项采用你标注的推荐选项。但澄清轮数和篇幅没有推荐，必须用户选。
   - "够了"：在第 4 步提前结束访谈。
   - "返回"：回到上一步重选。
   - "进度"：显示当前在第几步、已经选了什么。
4. 用户一次回复了好几项（例如"b, c, 分步骤"），就按顺序对应填好，不要重复追问。
5. 直接给内容，不要说"你问出了一个关键问题"之类的套话。

## 质量底线

- **先确认今天的日期**，并写进 `state.md`。涉及模型、产品、框架、协议、价格、政策等会变化的信息时，以联网核实的结果为准，不要凭训练记忆写。
- **不编造**：引文、数据、案例、链接都必须有真实出处。查不到就写"未找到可靠来源"，不要补一个看起来合理的。
- **事实和观点分开写**：观点要标明是谁的观点，或者标明是作者的判断。
- **图片不侵权**：不从搜索引擎里随手取图，规则见第 8 步。
- **引用要对得上号**：写报告和文章时，信源编号按 `sources.md` 的对照表查，不凭记忆写；写完后做引用校验（6.5）。
- **字数口径统一**：汉字按字计、英文按词计，两者相加；代码块和图表代码不计入。

## 文件存放

每次研究建一个目录：`research/<YYYY-MM-DD>-<主题英文短名>/`，所有产出都存在里面。`state.md` 记录当前步骤和用户的每一项选择，**每完成一步就更新一次**，这样流程中断后可以从中途继续。

`state.md` 的格式：

```markdown
# 研究状态
- 日期：2026-10-09
- 当前步骤：4（澄清访谈，第 2/5 轮）
- 研究模式：分步骤

## 已选
- 领域关键词：AI Agent
- 当前层次：初级实操者（有限经验）
- 学习目的：应用实践
- 题量：40
- 研究主题：……
- 澄清轮数：5
- 平台：公众号
- 篇幅：5000 字
- 配图：4 张，扁平插画风
- 语言：简体中文
```

## 工具缺失时的降级方案

- **不能开子 Agent**：第 6 步改为由你自己按视角逐个研究，流程和产出格式不变。
- **不能生图**：第 8 步只做流程图、示意图（代码绘制）和官方来源图片；需要生成的图，就把生图提示词写在占位处，交给用户自己去生成。
- **不能联网**：在开始前告诉用户这一点。本 skill 的研究质量依赖联网，不要假装自己联网核实过。
