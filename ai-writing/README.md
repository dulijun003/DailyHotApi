# 深度文章写作：Skill 与 n8n 工作流，两种方案对比

这里有两套实现，可以用**同一个主题**分别跑一遍，比较哪个效果好：

| | 方案 A：Claude Skill | 方案 B：n8n 工作流 v2 |
|---|---|---|
| 位置 | `.claude/skills/deep-article/` | `ai-writing/n8n/deep-article-workflow-v2.json` |
| 交互方式 | 聊天对话，随时追问、修改 | 网页表单，按步骤填写 |
| 研究方式 | Claude 自己联网搜索、精读、交叉验证 | 302.ai 的 o4-mini-deep-research（异步） |
| 写作 | Claude | Gemini（成稿 → 自审修订 → 配图方案） |
| 检查点 | 研究简报、大纲两处可确认 | 选题、澄清两处可填写 |
| 产物 | 一组 Markdown 文件（简报、笔记、来源、大纲、正文、自审、配图） | 结果页面显示（文章、配图方案、研究报告、任务书） |

---

## 方案 A：使用 Skill

### 1. 安装

**在 Claude Code 里（推荐）**

- 在本仓库目录下启动 Claude Code，Skill 会自动加载，不需要安装。
- 想在任何目录都能用，就复制到全局目录：

  ```bash
  mkdir -p ~/.claude/skills
  cp -r .claude/skills/deep-article ~/.claude/skills/
  ```

**在 Claude 网页版或桌面 App 里**

1. 打开设置中的 Skills 页面，上传 `ai-writing/deep-article-skill.zip`。
2. 需要同时开启代码执行和联网搜索，Skill 才能落盘文件、做研究。

### 2. 使用

直接说你想写什么就行。下面是几个例子：

```
/deep-article AI Agent 会取代 n8n 这类工作流工具吗？
```

```
帮我写一篇深度文章：为什么 2026 年大家都在谈"AI 原生组织"？
读者是中小企业老板，商业分析风格，6000 字左右，标准深度。
```

```
我只有一个方向：家庭储能。帮我拆一下选题，然后写一篇。
```

```
全自动模式，快速档：写一篇 3000 字的科普，主题是"咖啡因到底怎么影响睡眠"。
```

### 3. 流程和每步产物

```
定档（快速/标准/深度）→ [可选] 40 问选题 → 多轮多选题澄清 → 研究简报 ✅
→ 研究计划 → 联网研究 + 事实卡片 + 双源核查 → 大纲 ✅ → 成稿 → 自审修订 → 配图方案 / 公众号排版
```

所有文件保存在 `articles/<日期>-<slug>/` 下：

| 文件 | 内容 |
|---|---|
| `00-brief.md` | 研究简报，相当于整篇文章的"合同" |
| `01-plan.md` | 子问题拆解、研究视角、搜索清单 |
| `02-notes.md` | 事实卡片（每条事实都标有来源、等级、是否交叉验证） |
| `03-sources.md` | 来源清单，A、B、C 三级 |
| `04-outline.md` | 大纲和 3 个候选标题 |
| `article.md` | 正文，带脚注 |
| `review.md` | 自审记录 |
| `images.md` | 配图方案，含中英文生图提示词 |
| `article.wechat.html` | 公众号排版版（需要时才生成） |

### 4. 使用技巧

- **档位**：
  - 快速：1 轮澄清，约 3000 字
  - 标准（默认）：2 轮澄清，加大纲确认，约 5000 字
  - 深度：3–4 轮澄清，40 次以上搜索，可以多个研究员并行
- **写完之后可以继续要求**，例如：
  - "第 3 节论证太弱，补两个案例"
  - "整体再犀利一点"
  - "做成公众号排版"
  - "基于这篇研究，再写一篇面向投资人的版本"（会复用已有的研究笔记）
- **想改规则**：直接编辑 `references/` 下的文件。比如禁用表达清单在 `05-writing-style.md`，自审标准在 `06-review.md`。

## 方案 B：运行 n8n 工作流 v2

### 0. 先处理安全问题 ⚠️

旧工作流（35 号）的 302.ai Key 是明文写在节点里的。**先去 302.ai 后台作废这个 Key，再新建一个。** 新 Key 只放在 n8n 的凭证（Credentials）里，不要再写进节点。

### 1. 导入工作流

1. 下载 `ai-writing/n8n/deep-article-workflow-v2.json`。
2. 打开 n8n，新建一个工作流，然后用以下任一方式导入：
   - 右上角 `⋯` → **Import from File**，选择这个 JSON 文件；
   - 或者用文本编辑器打开 JSON，全选复制，在空白画布上按 `Ctrl+V` 粘贴。

### 2. 配置凭证（只需做一次）

**Gemini 凭证**

- 工作流里有 6 个"模型-xxx"节点，默认引用你现有的 `Google Gemini-TK` 凭证。在同一个 n8n 实例里导入的话，会自动绑定。
- 显示红色感叹号的话，逐个打开这 6 个节点，在 Credential 下拉框里选择你的 Gemini 凭证。

**302.ai 凭证（新建）**

1. 打开「提交深度研究」节点。
2. 在 **Credential for Header Auth** 里选择 **Create new credential**，填写：
   - **Name**：`Authorization`
   - **Value**：`Bearer sk-你的新key`（`Bearer` 后面有一个空格）
3. 保存后，打开「查询研究结果」节点，选择同一个凭证。

### 3. 检查模型（重要）

「启动」表单里的大模型选项已经从 gemini-2.5 换成了 3.x 系列。原因是 Google 现在限制了 2.5 系列的访问，只对以前用过的用户开放，新项目推荐 3.x。

| 选项 | 建议用途 |
|---|---|
| `gemini-3.8-flash` | 默认，速度和质量比较均衡 |
| `gemini-3.5-flash-lite` | 最快、最便宜，适合测试 |
| `gemini-3.1-pro-preview` | 质量最高，适合正式写作 |
| `gemini-2.5-pro` | 保留给仍有 2.5 访问权限的账号 |

运行时报 `model not found`，就打开「启动」节点，修改大模型下拉框的选项，改成你的 Key 能用的模型名。

### 4. 第一次测试（便宜、快）

1. 点击画布底部的 **Execute workflow**（旧版本叫 Test workflow），浏览器会打开测试表单。
2. 第一次建议这样填：
   - 研究主题：随便填一个
   - 需求澄清：**跳过澄清**
   - 研究模式：**只生成研究提示词**
   - 大模型：`gemini-3.5-flash-lite`
3. 提交后大约 10–30 秒，页面会显示生成的研究任务书。这一步验证 Gemini 凭证和表单链路都正常。

### 5. 完整运行

1. 再执行一次，这次选择：
   - 需求澄清：一轮澄清
   - 研究模式：**全自动（研究 + 成稿）**
2. 依次经过这些页面：
   - (可选) 40 问选题页：复制或改写一个选题后提交
   - 澄清问题页：按 `1: a  2: b,c` 的格式回答，也可以补充说明
   - 等待页：深度研究一般需要 **5–30 分钟**。页面保持打开，会自动跳到结果页
3. 结果页依次显示：最终文章（Markdown）→ 配图方案 → 原始研究报告 → 研究任务书。
4. 页面不小心关了也没关系：到 n8n 左侧 **Executions**，打开这次执行，点击「汇总结果」节点，就能看到全部内容。

### 6. 正式使用（固定网址）

1. 在工作流右上角点击 **Publish**（n8n 1.x 是打开 **Active** 开关）。
2. 正式表单地址是 `https://你的n8n域名/form/deep-article`，可以收藏起来，以后直接打开使用，不用再进 n8n 编辑器。

### 7. 可调参数（「配置」节点）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 深度研究模型 | `o4-mini-deep-research` | 可以改成 302.ai 支持的其他深度研究模型，比如 `o3-deep-research`（更贵、更深入） |
| 最大轮询次数 | 45 | 乘以轮询间隔就是最长等待时间（默认 45 分钟） |
| 轮询间隔分钟 | 1 | 每隔几分钟查询一次结果 |

### 8. v2 相比原工作流改了什么

| 原问题 | v2 的做法 |
|---|---|
| API Key 明文写在节点里 | 改用 n8n 凭证 |
| 用 `output[1].action.query` 判断研究是否完成，可能拿到半截结果，也可能报错 | 代码节点根据状态字段加正文内容判断，区分完成、等待、失败、超时；接口临时报错时继续轮询；超过次数显示失败页 |
| 没有最大轮询次数，可能死循环 | 有上限，超时后显示失败页，并附上研究任务书，方便手动拿去别处用 |
| 按中文标题用正则截取提示词，选英文时会提交空提示词 | 模型直接输出纯文本任务书，不需要截取 |
| 用 `JSON.parse` 解析模型输出，一出错就中断 | 全流程不再解析模型输出的 JSON |
| N 轮问答需要循环、Merge、模型复述历史，链路长而脆弱 | 改为一轮多选题批量澄清，问答记录由代码拼接 |
| 两个表单共用同一个 webhookId | 每个表单都有独立的 ID |
| 研究报告直接交给子工作流 | 增加三步：成稿（按风格、篇幅、脚注、去 AI 腔）→ 主编自审修订（对照研究报告核查事实）→ 配图方案 |
| 研究报告里的引用链接被丢掉 | 提取 url_citation，交给成稿环节生成参考资料 |
| 只能用 Gemini 2.5 | 换成 3.x 系列，可在下拉框中切换 |

> 想继续用原来的「图文」子工作流做排版和配图：在「汇总结果」节点之后接一个 Execute Workflow 节点，把 `完整文章` 映射为 `{{ $json['最终文章'] }}` 即可。

### 9. 常见问题

| 现象 | 原因和处理 |
|---|---|
| 模型节点报 `404` 或 `model not found` | 你的 Key 没有这个模型的权限。到「启动」节点改下拉框选项 |
| 「提交深度研究」报 `401` 或 `403` | 302 凭证的 Value 漏了 `Bearer `，或者 Key 已经作废 |
| 一直等待，最后显示 timeout | 302.ai 任务排队或失败。先去 302 后台查看任务状态和余额，再调大「最大轮询次数」 |
| 失败页显示 `failed` | 失败页下方的"接口返回"会显示 302 的原始错误信息 |
| 文章明显比要求的短 | 换成 `gemini-3.1-pro-preview`；或者研究报告本身太短，可以检查原始研究报告 |
| 表单页一直转圈 | 正常现象，深度研究在后台进行。也可以关掉页面，之后到 Executions 里看结果 |

## 怎么比较两种方案

用**同一个主题、同样的读者、风格和篇幅**各跑一次，按下表打分（1–5 分）：

| 维度 | 看什么 | Skill | n8n |
|---|---|---|---|
| 事实准确性 | 随机抽 5 个数字，打开来源核对 | | |
| 来源质量 | 一手来源占比，链接能否打开 | | |
| 洞见 | 有没有你在别处没看到的观点或信息 | | |
| 结构与逻辑 | 是层层递进，还是平铺罗列 | | |
| 文风 | AI 腔多不多，读起来顺不顺 | | |
| 符合需求 | 读者、风格、篇幅是否符合要求 | | |
| 可控性 | 中途能否纠偏，改稿是否方便 | | |
| 耗时 | 从开始到拿到成稿用了多久 | | |
| 成本 | 302 和 Gemini 的扣费，或者 Claude 的用量 | | |

我的预期是：

- **Skill** 在可控性、事实核查和改稿上更强。
- **n8n** 更适合"填完表单就走开"，以及以后接定时任务、批量生产（比如接 DailyHotApi 热榜自动选题）。

实际效果以你的测试为准。
