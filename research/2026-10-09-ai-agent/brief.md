# 研究简报
**核心问题**：在 Agent 会读取外部内容并调用工具的前提下，间接提示词注入为什么无法被根除，攻击链如何展开，哪些架构层面的防御能在可接受的代价下真正切断攻击链？

**不研究**：用户本人越狱；模型训练层面的对齐细节；传统 Web 安全（只作类比）；具体防护产品的评测。

**信源与时效**：A 级优先（论文、官方安全公告、厂商官方博客、研究机构的漏洞披露原文、OWASP 等标准）；攻击手法与防御研究优先近 12 个月；原理不限年份。

## 视角 1：原理机制：为什么"指令"和"数据"分不开
- 目的：讲清楚注入问题的根源，以及为什么它在模型层面只能缓解、不能根除
- 子问题：
  1. 大模型为什么没有"指令通道"和"数据通道"之分？和 SQL 注入对比：为什么不存在"参数化查询"的等价物？
  2. 间接注入造成实际危害需要哪些条件同时成立（不可信输入、敏感数据或能力、外传通道）？去掉其中任意一个会怎样？
  3. 模型层的缓解（指令层级训练、对抗训练、定界符和标记）能把攻击成功率降到什么程度？为什么无法降到零？
  4. 面对会根据防御调整策略的自适应攻击者，检测类防御的表现如何？
- 检索方向：英文为主。prompt injection fundamental / instruction-data separation / instruction hierarchy / lethal trifecta / adaptive attacks prompt injection defenses；中文检索国内安全团队的解读作补充
- 覆盖要点：要点 1；地图题 33

## 视角 2：攻击面与手法全景
- 目的：系统梳理不可信内容进入 Agent 的所有入口，以及攻击者想达成的目标
- 子问题：
  1. 入口有哪些：网页与搜索结果、邮件和日历、文档（含隐藏文字）、代码仓库和 issue、工具返回值、MCP 工具描述、RAG 知识库和长期记忆、其他 Agent 的输出、图片等多模态内容？
  2. 典型手法有哪些：隐藏文本、通过 Markdown 图片或链接外泄数据、工具描述投毒、工具定义上线后被篡改、记忆持久化投毒、在多个 Agent 之间传播？
  3. 攻击目标如何分类：数据外泄、越权执行动作、篡改输出、持久化、扩散传播？
  4. 不同类型的 Agent（浏览器 Agent、编程 Agent、办公助手、客服 Agent）主要暴露在哪些攻击面？
- 检索方向：indirect prompt injection taxonomy / MCP tool poisoning / data exfiltration markdown image / memory poisoning agent / OWASP LLM01；关注安全研究机构的分类框架
- 覆盖要点：要点 2

## 视角 3：真实案例拆解
- 目的：用公开披露的真实案例，把攻击链落到具体细节上
- 子问题：
  1. 选出 4–6 个公开披露、有一手资料（研究者原文或厂商公告）的案例，覆盖不同的入口和 Agent 类型
  2. 每个案例：攻击者在哪里放置恶意内容 → Agent 如何读到 → 触发了什么动作 → 数据或权限如何被利用
  3. 每个案例的根因属于哪一类（权限过大、缺少外传限制、缺少人工确认、信任了工具描述……）？
  4. 厂商是怎么修复的？修复是在模型层、产品层还是架构层？修复之后还有没有绕过？
- 检索方向：prompt injection vulnerability disclosure / zero-click AI agent exploit / MCP exploit / browser agent prompt injection / Copilot prompt injection；只采用研究者原文和厂商公告，媒体报道仅作线索
- 覆盖要点：要点 3

## 视角 4：防御手段逐个评估
- 目的：对每一类防御，评估它能防什么、防不住什么、代价是什么，以及有什么证据支持
- 子问题：
  1. 检测与过滤类（输入分类器、护栏模型）：在公开评测和自适应攻击下的效果如何？
  2. 提示层技巧（定界符、标记不可信内容、重复强调指令）：有多少作用？
  3. 架构类：双模型隔离模式、基于能力和数据流的方案（例如区分可信控制流与不可信数据）、学术界提出的安全设计模式。原理是什么，代价是什么？
  4. 权限与执行层：最小权限、网络出口白名单、禁止自动渲染外链和图片、高风险操作的人工确认、沙箱。各自切断攻击链的哪一环？
  5. 有哪些公开基准用来评估 Agent 抗注入能力？它们的局限是什么？
- 检索方向：design patterns securing LLM agents prompt injection / dual LLM pattern / CaMeL prompt injection / AgentDojo benchmark / spotlighting / prompt injection classifier evaluation / attacker moves second
- 覆盖要点：要点 4、要点 5

## 视角 5：参考架构与落地实践
- 目的：把防御手段组合成可落地的分层架构，并给出排查自己 Agent 的方法
- 子问题：
  1. 权威机构和主要厂商（OWASP、NIST 等，以及各大模型厂商的官方安全指南）推荐的分层防御思路是什么？
  2. 如何按"信任边界"画出一个 Agent 的数据流，找出不可信内容和敏感能力相遇的位置？
  3. 安全和可用性如何权衡：人工确认太多会导致用户疲劳，权限太紧会让 Agent 失去价值。业界是怎么取舍的？
  4. 浏览器 Agent、编程 Agent、企业办公 Agent 在架构配置上的差异
  5. 给初级实操者的排查步骤：按什么顺序检查自己的 Agent？
- 检索方向：OWASP top 10 agentic / LLM application security guidance / agent security architecture trust boundary / human in the loop approval fatigue；包括厂商官方的 Agent 安全文档
- 覆盖要点：要点 5（含 AI 建议的排查步骤）；地图题 29、34 部分覆盖
